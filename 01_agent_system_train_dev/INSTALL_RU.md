# Установка системы агентов TFM категории A

Версия 2.2 от 19 октября 2026 года. Пакет предназначен для финализации ровно 399 статей из рабочего Excel. Он содержит исправленные настройки, код, схемы, замороженные реестры, тесты и ТЗ. Реальная база ещё должна пройти обработку источников и итоговый аудит.

Пакет работает в **Claude Code на вашем компьютере**. Источники читаются из полной локальной копии разрешённой папки Google Диска. Отдельные ключи Google API этому варианту не требуются. Рабочая SQLite и результаты находятся в отдельной локальной папке проекта.

## 2 Установите программы один раз

Нужны **Python 3.12**, **Claude Code**, **LibreOffice**, а на Windows также **Git for Windows** для Bash. LibreOffice нужен для старого supplementary `.doc` и проверки Word supplements через PDF. В реестре есть также один `.xls`; его читает установленный вместе с пакетом xlrd.

Официальные страницы:

- Python: https://www.python.org/downloads/
- Claude Code: https://code.claude.com/docs/en/setup
- Git for Windows: https://git-scm.com/downloads/win
- LibreOffice: https://www.libreoffice.org/download/

Установка Claude Code в PowerShell Windows:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Установка Claude Code в терминале macOS/Linux:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

После установки откройте новый терминал. Для первого входа нужна учётная запись с доступом к Claude Code; авторизация выполняется через его штатный вход. Пакет не запрашивает пароль и не содержит ключей. Команды установки Claude проверены по официальной документации 18 октября 2026 года.

## 3 Установка на Windows

Откройте PowerShell в распакованной папке проекта. В примере ниже замените путь корпуса своим действительным путём.

```powershell
cd C:\TFM\TFM_AGENT_SYSTEM_v2_2
py -3.12 --version
py -3.12 tools/bootstrap.py --corpus "G:\My Drive\TFM_CORPUS_NORMALIZED"
.\.venv\Scripts\Activate.ps1
python tests/test_v2.py

claude doctor

```

Если Excel находится вне выбранного корня или обнаружены несколько одноимённых книг, укажите его явно:

```powershell
py -3.12 tools/bootstrap.py --corpus "G:\My Drive\TFM_CORPUS_NORMALIZED" --workbook "C:\TFM_INPUT\TFM_DATABASE_CLASS_A_WORKING.xlsx"
```

Если PowerShell блокирует только `Activate.ps1`, добавьте Python окружения в PATH текущего терминала и продолжайте без изменения системной политики:

```powershell
$env:Path = "$((Get-Location).Path)\.venv\Scripts;$env:Path"
python --version
```

Для этого пакета Git Bash должен быть доступен Claude Code. Если установленный Git не найден, проверьте путь Bash в настройках Claude Code по официальной инструкции. PowerShell как агентный shell в пакете отключён, чтобы все команды и hooks работали одинаково.

## 4 Установка на macOS и Linux

В терминале откройте папку проекта. Используйте установленный Python 3.12 и ваш действительный путь корпуса.

```bash
cd ~/TFM/TFM_AGENT_SYSTEM_v2_2
python3.12 --version
python3.12 tools/bootstrap.py --corpus "/absolute/path/TFM_CORPUS_NORMALIZED"
source .venv/bin/activate
python tests/test_v2.py
claude --version
claude doctor
claude
```

На macOS путь может находиться в `~/Library/CloudStorage/GoogleDrive-...`. Передайте абсолютный путь в кавычках. На Linux, если создание `.venv` сообщает об отсутствии venv/ensurepip, установите компонент venv для выбранной версии Python и повторите ту же команду.

`bootstrap.py` создаёт отдельное окружение, устанавливает зафиксированные зависимости, находит пути, строит точную карту Docling, проверяет оригиналы и хэши, импортирует Excel, применяет только детерминированную нормализацию метаданных, сохраняет связи публикаций и создаёт очередь. Входные PDF, supplementary и Excel не перезаписываются.

При успешной подготовке должны быть **399 studies**, **462 доступных оригинала** и `SETUP_COMPLETE`. Импорт содержит 312 непустых experiments и 17 357 исходных measurements. Эти числа относятся к исходному слою и не являются числом проверенных итоговых наблюдений. Предупреждения исходного QA сами по себе не означают готовность базы.

Если preflight вернул FAIL, исправьте конкретную причину и повторите команду. Он не отключает проверки при отсутствии файла, библиотеки или LibreOffice. Если хэш Excel отличается, нужен проверенный новый снимок; незаметно смешивать его с текущей базой нельзя.

## 5 Запустите автономную обработку

Внутри открытого Claude Code один раз подтвердите доверие к этой папке и выполните штатную авторизацию, если он их запросит. Команда `/agents` должна показать 12 проектных ролей. Затем введите:

```text
/tfm-finalize
```

Оркестратор выдаёт задачи максимум четырём агентам одновременно, сохраняет принятые результаты транзакционно и продолжает следующие задачи без вашего выбора партий. Первые 10 выбранных системой реальных статей проходят пилот; обнаруженные ошибки исправляются и перепроверяются до объявления готовности. Рутинные числовые исправления, однозначные связи и повторные чтения не требуют вашего подтверждения.

Docling — **UNVERIFIED** рабочий слой. Его текст, таблицы, прежние QA/DONE и результаты оцифровки помогают найти данные, но не подтверждают числа. Критичные значения проверяются по исходному PDF или original supplementary. Для спорных значений проверяются также Methods, легенда, заголовки и сноски. Исправления сохраняются в проверенном рабочем слое и журнале; исходный Docling не перезаписывается. Оцифровка релевантного графика обязательно учитывает среднее и видимые планки погрешности; прежний JSON только со средними не закрывает эту работу.

Агенты извлекают targets, необходимые модераторы, дизайн, сравнения, provenance и QA. Транскриптомные/метаболомные/протеомные матрицы и нерелевантная физиология не заполняются. При необходимости остаётся только указатель на актив. Биотические показатели имеют отдельные шкалы и estimands; ordinal scores не превращаются в lnRR. Недостаток n/SD или ковариации явно ограничивает использование данных. Проверенный вычислимый point target сохраняется в A_direct_yield/A_direct_dry_biomass и при отсутствующей variance; для анализа с весами существуют отдельные A_meta_*_weighted. Отсутствующая дисперсия не выдумывается и не уменьшает молча доступную ML-выборку.

## 6 Выполните один подготовленный человеческий аудит

TFM сохраняет итоговую проверку человеком. Система сама подготовит `work/human_review/audit.xlsx`, файл с доказательствами по всем плечам и, при необходимости, один список неразрешённых вопросов. Ручная повторная экстракция 35 статей не требуется.

В `audit.xlsx` откройте лист **Human audit**. Заполните жёлтые колонки `verdict`, `reviewer`, `notes`. `CORRECT` означает, что проверены все критичные поля всех плеч выбранного контраста. `INCORRECT` — найдена ошибка; опишите её. `UNSURE` — источник не позволяет уверенно подтвердить запись. На листе **Arm evidence** есть данные каждого плеча и ссылки на исходные представления, включая четыре клетки факторного контраста.

Число проверок: `k = min(N, max(20, ceil(0.15*N)))`, где N — уникальные retained contrasts в `evidence_long`. Одна строка, повторённая в нескольких marts, считается один раз. Проверять может автор или назначенный им человеческий эксперт. Агент не подписывает verdict от имени человека.

Сохраните Excel. В отдельном терминале той же папки, с активным `.venv`, импортируйте результат:

```bash
python tools/tfm.py human-audit-import work/human_review/audit.xlsx --reviewer "Имя Фамилия"
```

После импорта продолжите `/tfm-finalize` в Claude Code. Ошибки автоматически возвращаются на проверку. Подтверждённые человеком неизменившиеся записи сохраняют проверку; изменённые доказательства требуют повторного контроля. Неразрешённый существенный вопрос не закрывается формальным согласием моделей.

## 7 Как получить результат и продолжить после остановки

Готовый build создаётся в `exports/DATA_FREEZE_...`. В нём находятся финальные SQLite и Excel, CSV/Parquet, словарь, feature policy, QA, счётчики по marts, восемь групп data-stage figures с таблицами и `MANIFEST.json`. Финальный Excel содержит проверенные действующие таблицы и сохранённые исходные листы с префиксом `raw_`. Для анализа используйте verified таблицы и соответствующие marts.

`READY_TO_USE` допустим только при всех текущих PASS и `ready_to_use=true` в manifest. При открытом обязательном gate финальный export ничего не выпускает; диагностическая версия явно называется DRAFT. Пустой mart или малая выборка не исправляются вымышленными значениями. Готовность базы не означает достаточность данных для сложного ML.

Проверка выпущенных файлов из терминала:

```bash
python tools/tfm.py verify-build exports/DATA_FREEZE_ВАШ_BUILD
```

Для возобновления откройте ту же папку, активируйте `.venv`, затем:

```bash
claude --continue
```

В Claude Code снова введите `/tfm-finalize`. Завершённые задачи и принятые записи остаются в SQLite. Не создавайте новую базу и не копируйте поверх неё Excel из другой версии. Компьютер должен оставаться включённым; лимиты аккаунта, остановка приложения и сетевые сбои могут потребовать этого возобновления. Непрерывную работу через ограничения платформы пакет не обещает.

## 8 Что проверено и что проверить при запуске

В пакете есть исполняемые регрессионные тесты и отчёт проверки настоящего Excel. В реестре 423 PDF, 21 XLSX, 16 DOCX, один DOC и один XLS. Старые форматы обработаны отдельными readers; для DOC создаётся PDF-копия с сохранением хэша оригинала. Проверяются ключи между статьями, единицы, независимая проверка оригинала, полнота slots, source linkage, статистические формулы, QC, исправления, аудит и атомарный export. Полный список и фактический результат сохранены в `docs/VALIDATION_STATUS_RU.md`.

На тестовых источниках с известной истиной проверены S×B и A×B, нормализация g/kg, отличие mg/Mg, фигуры с калибровкой, SD/SE/доказанный CI, технические и биологические повторности, отдельные биотические MD и бинарные эффекты, исключение ordinal scores из lnRR и возврат ошибок человеческого аудита на автоматическую перепроверку. Эти проверки не измеряют полноту извлечения реального корпуса.

Результат проверок текущей версии приведён в docs/TEST_RESULTS.json. Код испытывался на Python 3.12.14 в текущей среде. Windows/macOS команды подготовлены по официальной документации; живой сеанс Claude Code на вашем компьютере здесь не запускался. Поэтому `claude doctor`, наличие 12 ролей, локальный self-test и реальный пилот являются обязательной проверкой установки. Полный source-by-source прогон 399 и человеческий аудит ещё предстоят. Конечная выборочная проверка не доказывает 100% безошибочность всей научной базы.

Точный смысл требований приведён в базовом ТЗ v2 из папки `docs` вместе с обязательным дополнением `BINDING_ADDENDUM_2_2_RU.md`. В части планок погрешности, SE по умолчанию и версии Excel применяется дополнение 2.2. Авторитетные источники: TFM, проверенный рабочий Excel и прямые указания заказчика; старые инструкции v1 не заменяют этот контракт.


## 9 Правила планок погрешности версии 2 1

Агенты самостоятельно ищут определения погрешности в подписи к рисунку, Methods, сносках и supplementary. Если авторы указали **SD**, сохраняется SD; если указали **SE**, сохраняется SE. Явный CI или другой интервал сохраняется в своей форме.

Для реально изображённых планок с неуказанным типом действует ваше правило: **принять SE**. В базе отдельно сохраняются исходный тип `UNCLEAR`, используемый тип `SE` и основание `USER_ASSUMED_SE`. Это допущение проекта, а не утверждение, что авторы статьи сообщили SE. У отсутствующей планки не появляется вымышленный SE или ноль.

Оцифровываются оба видимых конца планки либо один конец, если в оригинале показана только односторонняя планка. Код рассчитывает значения из калиброванных координат. Оценка разрешения не должна превышать 5% отдельно для среднего и ширины погрешности. При слишком коротких/нечётких планках агенты используют векторные данные PDF либо новый оригинальный render 360/600 dpi. Каждый render имеет отдельную ссылку на источник; старые координаты не переносятся на другое разрешение.

Среднее из таблицы сохраняется точным. Недостающая погрешность может дополняться с независимо проверенного графика той же группы, показателя и времени, при совместимых единицах и n. Источники среднего и погрешности сохраняются отдельно. При несовместимости сначала работает агент арбитража.

`SD = SE × sqrt(n)` вычисляется только при известном независимом n. Без n сохраняются SE и проверенный point target; взвешенная дисперсия не выдумывается. Истинно асимметричные границы сохраняются отдельно и не превращаются автоматически в симметричный SE.

Итоговые contrast/mart данные содержат `uncertainty_assumed`. Поле `weighted_reported_uncertainty_only_eligible` позволяет воспроизводимо исключить допущение SE в анализе чувствительности. Эти пометки не становятся предикторами ML.

Ваша рутинная работа с отдельными цифрами не требуется. Агенты выполняют оригинальную сверку, повторное чтение и исправления, продолжая другие статьи при локальной проблеме. В TFM §3.10 остаётся заключительный выборочный аудит человеком; система готовит для него ссылки на доказательства и показывает допущения явно.


## 10 Поиск урожайности после смены основного таргета

Ранняя база и Docling были ориентированы на биомассу. Полнота прежнего извлечения урожайности неизвестна. Во всех 399 статьях система заново обследует оригинальные статьи и supplementary: текст, таблицы, графики, панели, подписи, сноски и релевантные листы приложений. Предыдущие DONE и существующая выборка рисунков не заменяют эту проверку.

Главный таргет — масса урожая плодов; сухая биомасса остаётся второстепенным показателем. Поиск учитывает yield, harvest, harvested fruit mass, fruit/crop production, productivity, total/cumulative/marketable fruit weight и смысловые эквиваленты на языке оригинала. Этот список открыт. Даже без совпадения слов агент должен проверить количественные таблицы и оси по единицам, органу, знаменателю и периоду сбора. Дата сбора, harvest index, число плодов и масса одного плода сами по себе не заменяют урожайность.

Если первый проход не нашёл урожайность или не смог определить её наличие, обязателен второй независимый поиск по оригиналам, даже когда биомасса уже найдена. Второй проход не получает старые решения, инвентарь и таблицы Docling. Найденные дополнительные данные автоматически становятся заданиями на извлечение и проверку. До второй проверки вопрос о неясной урожайности автору не передаётся. Неустранимый вопрос после обеих проверок включается в общий список.

Для финального выпуска обязательна проверка primary_target_absence_independently_reviewed. Она не позволяет закрыть статью только на основании найденной биомассы, если отсутствие основного таргета независимо не проверено. Просмотр источника и согласие агентов сами по себе не доказывают стопроцентную полноту; полный прогон 399 и реальный аудит ещё предстоят.
