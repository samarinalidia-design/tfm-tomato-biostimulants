# SynerPlant Yield V4 — HARMONIZATION (только TRAIN, исследовательский этап)

**Вход:** `input/PRIMARY_EXPANDED_V31.csv` — побайтовая копия ML-файла V3.1 (`SynerPlant_Yield_V2/outputs/v31/yield/data/PRIMARY_EXPANDED.csv`,
403 контраста, 69 статей; SHA-256 в `input/input_manifest.json`). V2/V3.1, база данных и TEST **не изменялись и не читались**.

**Протокол:** те же внешние разбиения, что в V2/V3.1 (5 фолдов по статьям × 5 сидов), внутренняя настройка на 3 фолдах
обучающих статей, всё обучается внутри фолда. Точечное правило отбора — из V2 без изменений (выигрыш группового MAE ≥ 2 %,
≥ 3/5 фолдов, бутстреп-ДИ разницы < 0). Эталон — `row_median` (групповой MAE 0.3613, как в V3.1).

## Запуск
```
cd src
python h01_features.py      # флаги состава препарата, точность дизайна
python h02_cv.py            # 18 Python-кандидатов, 450 внешних обучений (~3 мин)
Rscript h03_rma_mv.R        # rma.mv (статья/контраст, общий контроль в V), location-scale rma
python h05_rma_summary.py   # точечные метрики R-моделей
python h04_intervals.py     # интервалы, покрытие, interval score, бутстреп
```

## Результаты

### Точечный прогноз (групповой MAE) — улучшения нет
| Кандидат | Совет | group-MAE | Δ к медиане | смещение |
|---|---|---|---|---|
| row_median (эталон) | — | **0.3613** | 0 | −0.166 |
| quantile_l1, FH, веса многоуровневой модели, robust scaling | 1, 3, 4 | 0.3618 | −0.1 % | −0.173 |
| quantile_l1, F2v3 (V3.1) | — | 0.3628 | −0.4 % | −0.161 |
| location-scale rma, scale ~ стресс | 5 | 0.3696 | −2.3 % | −0.063 |
| rma.mv, только свободный член (REML, точность + общий контроль) | 2, 3 | 0.3814 | −5.6 % | **−0.026** |
| partial pooling стресс × класс (EB) | 2 | 0.3754 | −3.9 % | −0.095 |
| mixed_ri, FH | 2 | 0.3962 | −9.7 % | −0.005 |
| MetaForest-тип (взвешенный RF), FH | 3 | 0.3990 | −10.4 % | −0.017 |
| rma.mv + стресс + флаги состава | 1, 2 | 0.4155 | −15.0 % | −0.043 |

Ни один кандидат не прошёл правило. Внутренняя настройка каждый раз выбирает максимальную регуляризацию, то есть почти
константу. Признаки состава, физические меры стресса и дозы, robust scaling и веса точности сигнала не добавили. 64 % дисперсии
lnRR приходится на различия между статьями (V3.1), а описанными условиями она не объясняется.

Медиана выигрывает по MAE, потому что MAE минимизируется медианой при правой асимметрии lnRR. Платой за это служит систематическое
занижение эффекта: −0.17 lnRR в CV и −0.32 на TEST V2. Многоуровневое среднее почти не смещено.

### Интервалы прогноза — есть устойчивое улучшение
Interval score (Gneiting & Raftery 2007; ширина + штраф за промах, меньше — лучше), баланс по статьям, бутстреп по статьям против
развёрнутого интервала V2.

| Цель | Метод | Покрытие | Полуширина | Interval score | Худшее семейство стресса |
|---|---|---|---|---|---|
| один контраст | V2: медиана + group CV+ | 0.908 | 0.975 | 2.910 | 0.683 |
| один контраст | **rma.mv-среднее + тот же group CV+** | **0.918** | **0.865 (−11 %)** | **2.666 (−8.4 %, ДИ < 0)** | **0.817** |
| один контраст | rma.mv-среднее + параметрический PI | 0.905 | 0.797 | 2.575 (−11.5 %) | 0.742 |
| вся статья сразу | V2: медиана + max-score CV+ | 0.951 / 0.907* | 1.402 | 3.199 | 0.955 |
| вся статья сразу | rma.mv-среднее + max-score CV+ | 0.950 / 0.899* | 1.315 (−6 %) | 3.042 (−4.9 %, ДИ < 0) | 0.951 |

\* доля статей, у которых покрыты все контрасты (номинал 0.90).

Location-scale по условиям (совет 5) интервалы **не улучшил**: модель разброса переобучается, покрытие 0.85–0.87 < 0.90,
по отдельным семействам стресса до 0.46–0.60.

## Выводы
1. Гармонизация **представления данных** (советы 1 и 4) на TRAIN метрики не улучшила. Вносить такие изменения в базу ради ML
   оснований нет.
2. Улучшение даёт **способ агрегации** (советы 2 и 3). Это многоуровневая модель (статья/контраст) с весами точности и учётом
   общего контроля, а прогноз для новой статьи идёт без её собственного сдвига. Интервал становится на 11 % уже при покрытии
   ≥ 0.90, смещение уходит, покрытие худшего семейства стресса растёт с 0.68 до 0.82. Цена — групповой MAE хуже на 5.6 %
   (ДИ разницы включает 0).
3. Порог интервального правила (покрытие ≥ 0.89, выигрыш ≥ 5 %, ДИ < 0) задан **после** первого прогона, поэтому это
   исследовательский вывод, а не пре-регистрированный. Изменения базы для него не нужны: `vi`, `n`, `shared_control_id` уже есть.
4. При переходе к TEST до вскрытия нужно пре-регистрировать замену точечной оценки и интервала (rma.mv-среднее + group CV+) и
   критерии, затем выполнить один прогон с пометкой о повторном использовании TEST.
